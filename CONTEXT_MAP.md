# 🗺️ CRYPTO BOT - CONTEXT MAP & ARCHITECTURAL DIGEST
> **Last Updated:** Feb 2026
> **Purpose:** Rapid context loading for AI agents. READ THIS FIRST.

## 1. Project Overview
A comprehensive Crypto Analysis Bot with a Flask-based Web Dashboard. It performs real-time analysis using multiple strategies (CVD, Funding Rates, Orderbook, Sentiment, etc.) and visualizes data for the user.

- **Stack:** Python, Flask, Pandas, CCXT, TA-Lib, HTML/CSS/JS (Vanilla).
- **Environment:** Development (Mac Local), Production (Oracle VM Ubuntu).
- **Service Management:** Systemd (`crypto-bot.service`, `web-dashboard.service`).

## 2. Core File Structure

### 🧠 Main Logic & Orchestration
| File | Role | Key Functions |
|------|------|---------------|
| `main.py` | **The Brain.** Fetches OHLCV, calculates technicals, runs AI models, orchestrates sub-modules. Writes to `web_results.json`. | `analyze_market_data`, `run_bot_loop` |
| `web_dashboard.py` | **The Interface.** Flask App serving API endpoints and HTML. Reads `web_results.json` and invokes reporting modules. | `/api/data`, `/api/report/*`, `sentiment_endpoint` |

### 📊 Reporting Modules (The Trackers)
These modules generate specific HTML/Text reports for the dashboard.
*   **`funding_rate_tracker.py`**: Analyzes Binance funding rates. (Key: `Coin`, `Funding Rate` as str %).
*   **`cvd_tracker.py`**: Cumulative Volume Delta analysis.
*   **`arbitrage_tracker.py`**: Price diffs between Binance/Bybit/OKX.
*   **`sentiment_tracker.py`**: Analyzes news sentiment. **Optimized**: Requires `news_data` injection.
*   **`cascade_liquidation.py`**: Calculates liquidation levels/risks.
*   **`ls_ratio_tracker.py`**: Long/Short ratios from multiple exchanges.
*   **`token_supply_tracker.py`**: Tokenomics/unlocks via CoinGecko. **Optimized**: Limits to top 8 coins, 0.2s sleep.
*   **`orderbook_depth.py`**: Detects buy/sell walls.
*   **`market_calendar.py`**: Fetches economic events & crypto news (`MarketImpactAnalyzer`).

### 📂 Data Storage
| File | Content | Schema Nuances |
|------|---------|----------------|
| `web_results.json` | Main dataset generated by `main.py`. | **Primary Key:** `"Coin"` (NOT "Symbol").<br>**Numeric Fields:** Often strings (e.g., "$100", "0.01%"). **Must sanitize before math.**<br>**Fields:** `Price`, `24h Volume`, `Funding Rate`, `Open Interest`. |
| `market_data.json` | Calendar/News data. | Stores `MarketImpactAnalyzer` results. |

## 3. Critical Implementation Details (DO NOT FORGET)

### 🔑 Data Key Standardization (FIXED)
All modules MUST use the following keys when reading `web_results.json`:
- **Symbol Identifier**: `coin.get("Coin")` (Do NOT use "Symbol")
- **Price**: `coin.get("Price")` or `coin.get("Current Price")` (Handle "$" and "," removal)
- **Volume**: `coin.get("24h Volume")` (Handle "," removal)
- **Funding**: `coin.get("Funding Rate")` (Handle "%" removal)

### 🚀 Optimization Settings
- **Token Supply**: Limited to **Top 8** coins per request to avoid CoinGecko timeouts (Free tier limits).
- **Sentiment**: `web_dashboard.py` uses global `MARKET_ANALYZER` to fetch news ONCE and passes it to `sentiment_tracker`.
- **Zero-Latency UI (New)**: `web_dashboard.py` now runs a **Background Thread** (`run_background_cache_updater`) that pre-calculates heavy reports (Funding, CVD, Token Supply, etc.) every 5 minutes. Endpoints serve from RAM cache instantly.

## 4. Deployment Workflow (Oracle VM)
The production environment runs on Oracle VM.
1.  **Local Dev**: Edit files in `scratch/crypto-analysis-bot`.
2.  **Push**: `git add . && git commit -m "msg" && git push`
3.  **Deploy Command**:
    ```bash
    ssh -o StrictHostKeyChecking=no -i id_rsa_oracle ubuntu@<SERVER_IP> "cd ~/crypto-analysis-bot && git pull && sudo systemctl restart crypto-bot"
    ```
    *(Note: `web-dashboard` service might be merged into `crypto-bot` or managed directly via python process).*
